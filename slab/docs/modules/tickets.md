# Help Requests

Raise and track support requests at `/admin/tickets`.

Help requests are how you ask the Slab platform team for help — a bug, a question, or something that isn't working. Every request you submit is sent straight to platform support.

## Raising a Request
Open **New Request** and fill in:

- **Subject** — required, a one-line summary
- **Description** — what happened, what you expected, and how to reproduce it
- **Category** — the area of the product involved
- **Priority** — low, medium, high, or urgent
- **Screenshot** — optional, but it usually saves a round trip

Each request gets a reference number in the form `T-000123`. Use it if you need to follow up.

## What Gets Sent With It
Alongside what you type, Slab attaches a quiet snapshot of the page you were on and any browser errors it saw. This is what usually tells support what actually broke, so leave it in place.

Your business name and site are attached too, so support knows which workspace to look at.

## Statuses
| Status | Meaning |
|--------|---------|
| Escalated | With platform support — where new requests start |
| Open | Logged, not yet picked up |
| In Progress | Someone is working on it |
| Resolved | Fixed, pending your confirmation |
| Closed | Finished |

Filter the list by status, priority, or category. The list also shows counts per status so you can see what's outstanding at a glance.

## The Conversation
Open a request to see the full thread. Add a reply at any time, with an optional file attachment — screenshots, exports, whatever helps. Replies are timestamped and attributed.

## Closing Things Out
- **Resolve** — mark it fixed. Use this once you've confirmed the problem is gone.
- **Close** — mark it finished and done with.
- **Escalate** — push it back to platform support with a note explaining why, if a resolved request wasn't actually resolved.
- **Delete** — remove the request entirely.

## Requests From Notes
A note in the Notes module can be sent straight to a help request. The note's title becomes the subject and its summary becomes the body. Re-sending the same note updates the existing request rather than opening a second one, and it never reopens a request you already resolved.
